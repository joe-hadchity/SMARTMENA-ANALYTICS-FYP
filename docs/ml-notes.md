# ML notes

## 1. Arabic sentiment analysis

- **Model**: `CAMeL-Lab/bert-base-arabic-camelbert-da-sentiment` (HuggingFace).
- **Why**: Pretrained specifically on Arabic (DA = dialectal Arabic + MSA blend), three-class classifier (`positive`, `negative`, `neutral`), good accuracy out of the box, ~150M parameters so it still loads on a dev laptop.
- **Integration**: Loaded via `transformers.pipeline("sentiment-analysis", ...)`. Lazy-loaded through an `lru_cache` wrapper so `uvicorn` boots in seconds; the first request pays the ~5-15s model load cost.
- **Inputs**: Either a single `text` or a batch `texts` (max 100 items via the backend validator). `lang` is currently advisory; we only ship the Arabic model in the MVP.
- **Outputs**: `{ text, label, score }` per input, plus `model_name`.
- **Limitations**: No fine-tuning on MENA ad/social data yet. Labels sometimes collapse "neutral" onto adjacent classes on short or emoji-heavy text. Fine-tuning on a small labeled subset is a logical follow-up after the MVP.

## 2. ROI prediction

- **Model**: `sklearn.ensemble.GradientBoostingRegressor` inside a single `Pipeline(pre=ColumnTransformer, model=GBR)` so inference is one `.predict(df)` call.
- **Features**:
  - Numeric (passthrough): `budget_usd`, `audience_size`, `duration_days`.
  - Categorical (one-hot): `channel`, `industry`, `country`.
- **Target**: `predicted_roi` - ratio of revenue to spend. `predicted_revenue_usd` is computed at request time as `budget_usd * predicted_roi`.
- **Dataset**: synthetic, generated by `ml-service/scripts/generate_roi_dataset.py`. Default 5 000 rows, seed 42. The generator encodes plausible (but invented) multipliers:
  - Channel: TikTok > Instagram > Google > Facebook > X.
  - Industry: ecommerce > fnb > retail > services.
  - Country: AE > SA > EG ≈ JO > LB.
  - Budget: log bump with diminishing returns.
  - Audience: log bump.
  - Duration: sweet spot around 21 days.
  - Gaussian noise (sigma ~12%).
- **Training**: `scripts/train_roi_model.py` does an 80/20 split, writes `artifacts/roi_model.joblib` and a sibling `artifacts/roi_model.metrics.json` with `mae`, `rmse`, `r2`.
- **Expected metrics** on the synthetic set: `r2` comfortably above 0.8 with the default config. These numbers are not evidence of real-world performance; they prove the pipeline is wired correctly.

## 3. Assumptions and limitations

- Synthetic ROI dataset is for MVP demo only. A real dataset (even small, anonymized) is needed before any production use.
- No drift or re-training pipeline; retraining = re-running the two scripts.
- No prediction confidence interval exposed yet. GBR supports quantile regression, which is a straightforward upgrade.
- The backend persists every prediction in Postgres (`Prediction` table) which gives us a free training-data accumulation mechanism for a future v2.

## 4. How to retrain

```bash
cd ml-service
python scripts/generate_roi_dataset.py --rows 10000 --seed 7
python scripts/train_roi_model.py
```

Then restart the ML service (the model is cached per-process).
